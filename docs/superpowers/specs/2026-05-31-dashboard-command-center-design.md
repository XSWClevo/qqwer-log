# 监控大屏科技指挥中心改造设计

## 目标

把当前“日志监控大屏”从普通后台统计页改造成更适合产品展示的“科技指挥中心”首页，优先提升视觉冲击力、动态感和图表联动体验，同时避免因数据集字段差异导致大片空白。

这次改造采用以下明确取向：

- 视觉风格：科技指挥中心
- 使用场景：产品展示屏
- 数据策略：混合策略

## 现状问题

当前页面已经完成基础可用性改造，但存在四类核心问题：

1. 视觉层级偏弱。页面结构更像普通后台工作台，缺少首屏舞台感、节奏感和动态反馈。
2. 指标卡静态化。平台指标和日志数据集指标都是固定卡片，缺少点击后的下钻图表和联动分析。
3. 数据能力固定写死。不同数据集字段不同，但页面区域是固定的，导致部分图表天然空白。
4. 图表降级不优雅。趋势图、级别分布、Top 实体等视图在字段缺失或映射不足时容易直接空白，影响展示效果。

## 产品原则

### 1. 首屏优先冲击力

首页第一屏要能在 3 秒内建立“平台有实时数据、有规模感、有动态反馈”的感知，不再把页面入口做成一组朴素卡片。

### 2. 展示优先但不伪造数据

不允许为了好看编造不存在的指标；允许在字段不足时切换到同等级替代视图，保证页面连续性。

### 3. 能力驱动而不是坑位驱动

页面不再预设“Top 主机”“Top 应用”必须出现，而是由当前数据集支持的字段能力决定显示哪些图表。

### 4. 展示与交互并存

首页不是纯大屏海报。关键指标必须可以点开看到趋势、分布、明细或侧滑详情，兼顾演示和日常使用。

## 推荐方案

采用“舞台化混合型”方案：

- 上半区是展示舞台，负责科技感、动效、关键数字和主趋势图。
- 下半区是分析工作台，负责点击卡片后的趋势展开、动态编排图表和事件流。
- 后端按“数据集能力”返回可展示维度，前端按能力生成图表矩阵。

这个方案比纯视觉大屏更稳，也比纯驾驶舱更有冲击力，适合产品展示屏。

## 信息架构

页面调整为四层结构。

### 第一层：指挥中心头图区

头图区承载首屏视觉冲击与主状态信息，包含：

- 当前数据集名称与状态
- 数据接入状态
- 可查询数据集数量
- 日志总量
- 日志体积
- 实时吞吐 / EPS
- 错误率 / 高危日志
- 一个主趋势图

布局采用左文右图结构：

- 左侧为大数字与关键状态
- 右侧为主趋势图或组合趋势图
- 背景使用低频动态网格、渐变流光、扫描线或轨迹装饰，但避免廉价粒子堆砌

### 第二层：可交互核心指标区

当前固定 KPI 卡片改成可交互能力卡。

每张卡片支持：

- 数字滚动动画
- hover 边缘发光
- 点击后展开迷你图表或切换旁侧分析面板

建议的核心卡片：

- 日志总量
- 日志体积
- 当前吞吐
- 错误率
- 高危日志
- 活跃范围

点击行为示例：

- 日志总量：展示分时折线图
- 日志体积：展示体积趋势图，自动换算 MB / GB / TB
- 错误率：展示错误率波动线
- 高危日志：展示高危级别趋势或最近异常事件
- 活跃范围：展示实体排行或能力提示

### 第三层：动态编排图表区

图表区不再固定为“趋势 + 分布 + Top 主机 + Top 应用 + 高频错误”。

改成“图表能力池 + 编排规则”：

- 如果支持 `timestamp + severity`，展示趋势图和级别分布
- 如果支持 `hostname`，展示主机排行
- 如果支持 `appname`，展示应用排行
- 如果不支持实体字段，则替换成消息热词、高频消息、最近异常时间密度、日志来源趋势等通用视图

页面始终保证：

- 至少 1 个主趋势图
- 至少 2 到 3 个次级视图
- 不出现大块空白图框

### 第四层：事件流明细区

底部保留最近日志，但样式升级为“事件流”：

- 更强的等级色带
- hover 高亮
- 行点击打开侧滑详情
- 可与上方指标和图表联动过滤

## 数据展示模型

后端要把 dashboard 能力拆成三层。

### 1. 通用指标

几乎所有日志表都尽量支持：

- 日志总量
- 日志体积
- 时间趋势
- 最近日志
- 错误数量
- 错误率
- 吞吐 / EPS

### 2. 半通用指标

需要部分标准字段：

- 级别分布
- 高危日志
- 高频消息
- 时间热力

### 3. 扩展指标

依赖 `hostname`、`appname`、`source` 等扩展字段：

- Top 主机
- Top 应用
- 来源分布
- 节点活跃度

前端不再写死卡片和图表集合，而是根据后端返回的“支持能力列表”动态渲染。

## 指标与视图降级策略

### 日志总量与体积拆分

“日志总量”与“日志体积”必须拆开：

- 日志总量：条数，例如 `11.9K`
- 日志体积：大小，例如 `842 MB`

日志体积在 v1 可按 `raw` 或 `message` 长度求和近似估算，不要求一步到位对齐 ClickHouse 真实物理存储。

### 空白视图替代规则

当某类视图不可用时，采用以下规则：

- 缺 `hostname`：主机排行替换为消息热词或来源趋势
- 缺 `appname`：应用排行替换为高频消息或时间密度图
- 缺 `severity`：级别分布替换为消息等级不可用提示 + 最近异常趋势
- 缺实体字段但有消息字段：优先保留消息类图表

### 明确提示但不打断展示

替代视图加载后仍要展示轻量提示：

- “当前数据集不支持主机维度，已切换为消息热词”

这样既真实，又不破坏演示连贯性。

## 动效与视觉语言

动效目标是“高级感”和“数据活性”，不是特效堆叠。

建议使用：

- 动态背景光带或低频网格漂移
- 首屏主趋势图轻微流动动画
- 指标数字滚动
- 卡片 hover 边缘流光与投影变化
- 图表切换淡入 / 上浮过渡
- 异常状态轻微脉冲提醒

避免：

- 大面积重粒子背景
- 高频闪烁
- 过强霓虹边框
- 装饰压过内容

## 图表建议

建议图表组件以 ECharts 为主，图形类型如下：

- 主趋势：面积折线混合图
- 级别分布：环图或极坐标柱图
- 实体排行：横向条形图
- 时间密度：热力图
- 高频消息：条形图或标签云
- 指标卡内联分析：sparkline / mini area chart

## 组件与边界建议

前端建议拆出以下职责单元：

- `CommandCenterHero`：头图区和主趋势
- `InteractiveMetricDeck`：可点击指标矩阵
- `MetricDrilldownPanel`：指标下钻图表面板
- `AdaptiveInsightBoard`：动态编排图表区
- `EventStreamTable`：底部事件流
- `useDashboardCapabilityLayout`：根据后端能力生成视图布局

后端建议补以下能力：

- `dashboardCapabilities`：返回当前数据集支持哪些视图
- `storageVolume`：返回日志体积估算值
- `metricDrilldowns`：返回指标卡点击后需要的附加序列

## 错误处理

错误处理分为三层：

1. 接口级失败：显示页面级 warning，但保留可展示区域
2. 单视图失败：该视图替换为降级卡，不影响其它区域
3. 字段能力不足：按替代规则自动切换视图，并显示轻提示

不再因为一个扩展字段缺失就把整块 dashboard 降级为空状态。

## 测试与验收重点

### 视觉验收

- 首屏有明显舞台感，不像普通后台
- 明暗主题都正常
- 指标卡、图表区、事件流之间层次分明

### 交互验收

- 点击指标卡可展开趋势或分析视图
- 数据集切换后图表矩阵自动重新编排
- 图表为空时有替代视图或明确提示

## Implementation Notes

- 首页真实入口是 `/`，路由名为 `Dashboard`；旧文档中的 `/dashboard` 仅作为概念页名，不作为实际访问路径。
- `regex_logs` 或其它字段不完整的数据集缺少 `hostname/appname` 时，首页使用 capability fallback 选择替代视图，避免保留大面积空白图框。
- `timestamp` 是时间范围聚合的硬前置条件；缺失时后端直接返回数据集级空状态，不继续拼接 ClickHouse 聚合 SQL。
- `severity` 缺失时，趋势、级别分布、高频错误和最近高风险日志局部降级；总量、EPS、体积估算等仍可继续展示。
- 日志体积为 `raw` 或 `message` 字段长度的近似估算值，不等同于 ClickHouse 物理存储占用。
- 前端视觉收敛为工作台式科技指挥中心：使用紧凑布局、8px 主卡片圆角、稳定 hover 位移和现有 `var(--macos-*)` 主题变量，保证暗色模式不出现突兀白底。

### 数据验收

- `syslog_logs` 这类标准字段表可显示完整视图
- `regex_logs` 这类缺少主机/应用字段的表不会大片空白
- 日志总量与日志体积能同时展示

## 分期策略

### 第一期：结构与能力模型

- 重做首页结构
- 核心指标卡支持点击
- 增加日志体积指标
- 建立 dashboard 能力返回与动态布局

### 第二期：联动图表与替代视图

- 指标卡下钻图
- 图表区动态编排
- 空白视图自动替代
- 事件流联动过滤

### 第三期：视觉强化与动效

- 动态背景
- 数字滚动
- 发光边框
- 图表切换动画

## 结论

这次改造不是简单“美化页面”，而是把首页从固定统计坑位升级为“能力驱动的科技展示指挥中心”。

核心收益：

- 首页观感显著提升，更适合产品展示
- 不同数据集的字段差异不再直接造成大片空白
- 指标不再只是静态数字，而是进入可展开、可联动、可解释状态
- 后续新增数据集类型时，首页可以继续复用能力编排模型扩展
